# SKILL.md authoring template

Every skill in skills/ follows this structure. Bodies are hand-authored
distillations of research software engineering practice; the
references.md file next to each SKILL.md and the "Related skills" block
inside it are pipeline-generated and never hand-edited.

## Frontmatter

```yaml
---
name: rseng-<topic>
description: >-
  <Third person, starts with what the skill covers, then explicit trigger
  conditions: "Use when the user asks about X, wants to Y, or mentions Z.">
license: CC-BY-4.0
metadata:
  version: 0.1.0
---
```

Rules for `description`: one sentence of coverage plus concrete triggers;
no first person; distinct from every sibling skill (checked in the
cross-review pass); mention both everyday phrasing ("write tests") and
domain terms ("CI matrix") a user might use. The coverage half doubles
as the skill's scope line in the adapter renders, so lead with it.

## Body structure

1. Title heading, then a one-paragraph overview of when and why.
2. Guidance sections - short, imperative, agent-actionable. Prefer
   checklists and decision rules over prose. Name sibling skills inline
   (for example `(rseng-ci-cd)`) where a neighbouring practice takes over.
3. `## Working with this skill` - point at references.md (generated:
   the skill's verified Learn-more pointers).
4. `Learn more (verified):` - the curated external links, as an
   indented bullet list of `<url> - <short label>` entries. This block
   is the input the references generator reads; keep it current and
   verified (the link checker probes every URL).
5. The `<!-- related-skills:begin -->` ... `<!-- related-skills:end -->`
   block at the end is generated by `related_skills.py` from its curated
   map - never edit it by hand; edit the map and regenerate.

## Constraints

- Body <= 500 lines; aim for 120-250.
- Plain ASCII; no emoji or decorative glyphs.
- Every external URL in a body must sit in the "Learn more (verified)"
  list and survive the link checker - no hand-typed, unverified links
  scattered through the prose.
